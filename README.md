# Govargus

How the United States is doing, measured: official indicators since 1980 drawn over every presidential term, with NBER recessions and the laws, trade actions, Fed moves and shocks that plausibly moved them. No scores. Each term is shown next to the trend it inherited (see `/about`).

## Running it

Everything runs in Docker through `make`. Nothing needs Node on the host.

```sh
make install   # npm install (network)
make data      # fetch every indicator into src/data/series (network)
make policy    # fetch executive orders + public laws into src/data/policy (network)
make check     # validate indicators / presidents / events data (offline)
make build     # static site into dist/ (offline)
make dev       # dev server on http://127.0.0.1:4321
```

## Layout

| Path | What |
|---|---|
| `src/data/indicators.json` | Indicator definitions: source series, unit, group, and whether terms are summarized by `change` or `average` |
| `src/data/presidents.json` | Terms (the last one has `end: null`) |
| `src/data/events.json` | Hand-curated policy timeline, sorted by date, each tagged with the indicators it affects |
| `src/data/series/*.json`, `recessions.json` | Generated by `make data`; committed so builds are offline and reproducible |
| `src/data/policy/` | Generated by `make policy`: every executive order (Federal Register, 1994+) and public law (Congress.gov, 1981+). Finished Congresses are cached and never re-fetched |
| `src/lib/data.ts` | Loading, formatting and per-term stats |
| `src/components/LineChart.astro` | Server-rendered SVG chart (terms, recessions, events); hover via a small script in the layout |

## Adding an indicator

Add an entry to `indicators.json` with a FRED series id, then run `make data && make check && make build`.

## Keys

Only Congress.gov needs one: a free [api.data.gov key](https://api.data.gov/signup/), passed as `CONGRESS_API_KEY` (env for `make policy`, a repo secret for CI). Without one it falls back to `DEMO_KEY` (10 requests/hour), and the law backfill completes over several runs.

## Automation

`.github/workflows/data.yml` re-fetches indicators and the policy record every Monday and commits any changes.

## Hosting

Intended for Cloudflare Pages, connected to this repo: build command `npx astro build`, output directory `dist`, environment variable `NODE_VERSION=24`. Every push to `master`, including the weekly data commits, triggers a rebuild.
