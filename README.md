# Govargus

How the United States is doing, measured: official indicators since 1980 drawn over every presidential term, with NBER recessions and the laws, trade actions, Fed moves and shocks that plausibly moved them. No scores. Each term is shown next to the trend it inherited (see `/about`).

## Running it

Everything runs in Docker through `make`. Nothing needs Node on the host.

```sh
make install   # npm install (network)
make data      # fetch every indicator into src/data/series (network)
make policy    # fetch executive orders + public laws into src/data/policy (network)
make records   # fetch vetoes, pardons and deportations into src/data/records (network)
make check     # validate indicators / presidents / events data (offline)
make build     # static site into dist/ (offline)
make dev       # dev server on http://127.0.0.1:4321
```

## Layout

| Path | What |
|---|---|
| `src/data/indicators.json` | Indicator definitions: source series, unit, group, and whether terms are summarized by `change` or `average` |
| `src/data/presidents.json` | Terms (the last one has `end: null`) |
| `src/data/events.json` | Hand-curated policy timeline, sorted by date, each tagged with the indicators it affects |
| `src/data/series/*.json`, `recessions.json` | Generated by `make data`; committed so builds are offline and reproducible |
| `src/data/policy/` | Generated by `make policy`: every executive order (Federal Register, 1994+) and public law (Congress.gov, 1981+). Finished Congresses are cached and not re-fetched once six months past their end |
| `src/data/records/` | `vetoes.json`, `clemency.json`, `deportations.json` generated by `make records` from the House historian, the DOJ Pardon Attorney and DHS statistics; `executive-order-ranges.json` is hand-entered from the National Archives and checked against the Federal Register by `make check` |
| `src/lib/data.ts` | Loading, formatting and per-term stats |
| `src/lib/yearly.ts`, `src/lib/records.ts` | Calendar-year tables for the indicator pages; per-term counts for the record pages |
| `src/lib/seo.ts` | Page titles, meta descriptions, canonical URLs and JSON-LD (Dataset, breadcrumbs) |
| `src/pages/og/[id].png.ts` | Social preview images, rendered to PNG at build time with resvg and the fonts in `src/assets/fonts/` |
| `src/components/LineChart.astro` | Server-rendered SVG chart (terms, recessions, events); hover via a small script in the layout |

## Adding an indicator

Add an entry to `indicators.json` with a FRED series id and a `keyword` (the phrase people search for), then run `make data && make check && make build`.

## Keys

Only Congress.gov needs one: a free [api.data.gov key](https://api.data.gov/signup/), passed as `CONGRESS_API_KEY` (env for `make policy`, a repo secret for CI). Without one it falls back to `DEMO_KEY` (10 requests/hour), and the law backfill completes over several runs.

## Automation

`.github/workflows/data.yml` re-fetches indicators, the policy record and the presidential records every Monday and commits any changes.

## Pages and search intent

Each indicator has two pages aimed at different searches: `/indicators/<id>` is the series year by year ("gas prices by year") and `/compare/<id>` is every term side by side ("gas prices by president"). The indicator's `keyword` in `indicators.json` is the phrase both titles use. `/executive-orders`, `/vetoes`, `/pardons` and `/deportations` count each record by term.

## Hosting

Cloudflare Workers (static assets), connected to this repo. Config is in `wrangler.jsonc`; Node 24 comes from `.node-version`.

| Setting | Value |
|---|---|
| Build command | `npx astro build` |
| Deploy command | `npx wrangler deploy` |
| Non-production branch deploy command | `npx wrangler versions upload` |

Every push to `master`, including the weekly data commits, triggers a rebuild and deploy.
